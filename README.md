# Primitive DB — консольная база данных

Учебный проект № 2. **Семёшин, группа М26-555**.
Python 3.12+, процедурный стиль без пользовательских классов.
Создание таблиц, CRUD, JSON-хранилище, строгая проверка типов,
декораторы и кэширование через замыкание.

## Установка и запуск

Нужен [uv](https://docs.astral.sh/uv/getting-started/installation/).
В корне скачанного репозитория:

```bash
make install         # uv sync --locked
make run             # uv run database
```

Без make:

```bash
uv sync --locked
uv run database
```

Зависимости зафиксированы в `uv.lock`. Используется uv из первой части
задания: описание пакета — `[project]`, инструменты разработки —
`[dependency-groups].dev`. Секции Poetry не нужны.

## Полный сценарий

```text
create_table users name:str age:int is_active:bool
list_tables
insert into users values ("Sergei", 28, true)
select from users
select from users where age = 28
update users set age = 29 where name = "Sergei"
select from users where age = 29
info users
delete from users where ID = 1
n
delete from users where ID = 1
y
drop_table users
y
exit
```

`help` выводит все команды. Названия команд нечувствительны к регистру;
имена таблиц и столбцов чувствительны. Таблицы и столбцы должны иметь имена,
допустимые для идентификаторов Python. `ID:int` добавляется автоматически:
его не передают в `create_table` и `insert`, а изменение через `update` запрещено.
Новый ID равен максимальному существующему ID + 1 (в пустой таблице — 1).

Поддерживаются `int`, `str`, `bool`. Все значения обязательны. Строки нужно
заключать в одинарные или двойные кавычки, логические значения — `true/false`.
Для кавычки внутри строки используйте другой вид внешних кавычек.
Запятые, пробелы, скобки и знаки равенства внутри строк сохраняются.
`where` и `set` поддерживают одно равенство; выражения AND/OR и SQL не исполняются.
Удаление записей требует `where`, а выборка без него возвращает всю таблицу.

## Декораторы и кэширование

- `handle_db_errors` централизует обработку `KeyError`, `ValueError`,
  `FileNotFoundError` и ошибок файловой системы. После ошибки можно вводить
  следующую команду; неуспешные результаты не сохраняются.
- `confirm_action(action_name)` запрашивает подтверждение `drop_table` и
  `delete`. Только `y` (без учёта регистра и окружающих пробелов) выполняет
  операцию; любой другой ответ отменяет её.
- `log_time` измеряет `insert` и `select` через `time.monotonic()` и печатает
  `Функция select выполнилась за X.XXX секунд`.
- `create_cacher()` хранит словарь в замыкании. Повторный `select` использует
  сохранённый результат. Ключ включает снимок всех строк и условие с типами,
  поэтому изменение данных, в том числе извне, меняет ключ. Возвращаются копии
  строк, чтобы вызывающий код не испортил кэш. Хранятся до 128 запросов.

Кэш экономит повторную фильтрацию, но не загрузку JSON и не вычисление ключа.
При небольших таблицах время может округляться до `0.000` секунд.
Кэш живёт только до завершения процесса.

## Хранение и архитектура

Файлы создаются **в текущем каталоге запуска**:
`db_meta.json` содержит схемы, `data/<таблица>.json` — записи.
Данные сохраняются после каждой успешной изменяющей команды.
Первый запуск без метаданных создаёт пустую базу. Отсутствие файла уже
созданной таблицы и повреждённый JSON диагностируются как ошибки.
Один файл заменяется атомарно; транзакций между файлами и блокировок
для одновременной работы нескольких процессов нет.

```text
src/primitive_db/
├── __init__.py
├── main.py          # точка входа
├── engine.py        # цикл, команды, вывод и координация сохранения
├── core.py          # схемы и CRUD
├── utils.py         # чтение/запись JSON
├── parser.py        # команды, values, where, set
├── decorators.py    # обёртки и замыкание
└── constants.py     # типы, пути, настройки
```

В коде приложения используются только `json`, `shlex`, `time`, `os`,
`prettytable` и `prompt`. `pytest` и `ruff` — инструменты разработки.

## Проверки и сборка

```bash
make lint
make test
make build
uvx twine check dist/*
```

Автотесты покрывают полный CRUD, отмену и подтверждение удаления, сохранение
между отдельными запусками, ошибки типов и синтаксиса, отсутствующие и
повреждённые файлы, уникальность ID, актуальность кэша и замер времени.
GitHub Actions запускает линтер, тесты и сборку на push и pull request.

Проверить установку собранного wheel отдельно от исходников:

```bash
uv venv /tmp/primitive-db-check
uv pip install --python /tmp/primitive-db-check/bin/python dist/*.whl
/tmp/primitive-db-check/bin/database
```

Рабочий процесс: изменения в отдельной ветке, проверки, затем слияние в main.
База, окружение, кэши и сборочные файлы исключены через `.gitignore`.
